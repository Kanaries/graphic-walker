# 自有工作表渲染器：需求与验收 v0.3

日期：2026-11-06。状态：现有 GW specification、渲染库边界及首版核心范围已确认并实施。本文定义验收要求，当前完成度与证据见 [实施记录](./worksheet-renderer-implementation.md)；决策与架构见 [alignment](./worksheet-renderer-alignment.md) 和 [design doc](./worksheet-renderer-design.md)。

## 1. 产品目标

使用自有图表库和新的 renderer 渲染现有 Graphic Walker specification。用户继续使用原有字段、配置和存储流程；增加行列维度后，图表形成层级表头和对齐的绘图区，选择、轴、滚动与导出作用于同一张工作表。

用户不需要知道 pane、图表实例或虚拟化窗口。图表库负责这些机制，并作为 monorepo 独立子包供 GW 接入。

首版聚焦多层行列嵌套、统一布局、单 Canvas 双向虚拟滚动、可交互 SVG、基础图形与选择。双轴和多标记层可后续扩展。本期实施范围是图表库、renderer 及必要的结果数据接口适配，不包含计算体系研发。

v0.3 明确沿用 IChart 的 `encodings / config / layout`，不引入 VizQL 或第二套用户 specification。renderer 内部可生成渲染参数和布局计划，不要求用户编写、保存或迁移到这些内部结构。Vega-Lite 风格仅作为局部配置的兼容方式，范围由设计文档列出。

固定运算沿用 GW 既有计算 DSL，自定义运算沿用现有 SQL 能力。这些是前置能力。现有 spec 中的聚合、过滤和计算字段继续走既有流程；本期不新增计算语法、运算符、查询规划器或执行器。库只接收这些流程的结果，完成刻度、坐标、堆叠位置及布局等渲染计算。

| 本期交付职责 | 实现位置 |
| --- | --- |
| 将现有 GW spec 与计算结果映射为内部渲染参数 | 新 native renderer 的 GW 适配层 |
| 层级显示、pane 布局、坐标轴、图形编码、Canvas/SVG、虚拟滚动、命中检测 | 本图表库 |
| 按显示范围读取已有结果及元数据 | 结果供数适配层；库负责发起范围读取和有界缓存，不决定结果的计算方式 |

## 2. 术语与行为边界

| 术语 | 本提案中的含义 |
| --- | --- |
| Worksheet | 一张工作表，拥有一份声明、一套布局与交互状态和一个运行实例 |
| Header | 离散成员形成的层级表头，父节点可跨多个叶位置 |
| Pane | 共享一套局部坐标系的绘图区；不是一个独立图表实例 |
| Band | pane 内的离散位置，例如一个 Region 中的不同月份 |
| Mark | 柱、点、线、矩形或文本对应的可视标记 |
| 输入记录 | 外部已确定含义的一条显示数据；库不推断或改变它的聚合粒度 |
| Domain | 数据取值范围；与像素范围及滚动窗口不同 |
| 逻辑单元槽位 | 行位置与列位置的交叉，可为空，不要求分配对象 |
| 虚拟化 | 只检索、加载和构建当前需要的内容，同时保留整张工作表的语义 |

"不限固定嵌套层数"表示同一结构支持继续增加层级，不能写死二层、三层模板。它不表示无限内存、无限 Canvas 像素或任意大小的 SVG。

层级表头、pane 和坐标轴是显示目标。字段语义以现有 GW spec 为准，通过 renderer 映射到这些显示结构，不要求用户采用 Tableau 的字段表达式或另一套语法。

## 3. 典型使用场景

| 场景 | 操作与预期 |
| --- | --- |
| U1：多层业务比较 | Rows 放 Region、Category、Subcategory，Columns 放 Year 和并列 Sales/Profit；保留父子表头、不同度量单位和跨 pane 对齐 |
| U2：分组趋势 | Region 划分 pane，Month 在 pane 内定位；折线连接同一序列的月份，不为每个月创建单点图表 |
| U3：高基数浏览 | 行方向十万叶位置、列方向千级叶位置；双向滚动和跳转时仅加载窗口附近内容，冻结表头仍能定位当前分组 |
| U4：折叠与展开 | 折叠后调整表头和布局；需要汇总值时由 GW 提供。等待数据时显示加载状态，库不从子级值重算 AVG/COUNTD |
| U5：选择与后端切换 | 选中的 mark 滚出再滚回仍保持选择；切换 SVG 后选择身份、坐标范围和图形含义不变 |
| U6：保存与分享 | 保存工作表、重新加载、撤销和重做不丢深层字段；导出包含指定范围，而非意外只含缓存中的数据 |

## 4. 首版必需能力

所有 R 项都是首版验收项。实现顺序可以分阶段，不能以后续优化名义省略。

| ID | 需求 | 可验收行为 |
| --- | --- | --- |
| R01 | 独立子包 | `@kanaries/worksheet-renderer` 可在 GW store 之外运行；核心不依赖 React，React 为独立入口；有构建产物和类型声明 |
| R02 | 自有双后端 | Canvas 2D 和原生 SVG 均支持显示、更新、滚动、选择；共用语义与几何，不调用第三方整图引擎完成新路径 |
| R03 | 单 Canvas 实例 | Canvas 模式只有一个可见图表 Canvas，包含表头、轴、主体与高亮；没有逐 pane Canvas/子图表实例 |
| R04 | 递归行列结构 | 由现有 rows/columns 列表形成任意深度层级、并列度量和空交叉位置；不要求用户编写表代数；不因深度丢字段 |
| R05 | 字段与数据绑定 | 字段实例、记录和序列有稳定身份；离散/连续决定显示方式；Color/Detail 只用于给定记录的编码和序列身份，不触发聚合 |
| R06 | 统一布局 | 层级表头、父级跨度、共享条带、轴槽和 pane 边界对齐；长文本、中英文、负值、空值和不等长层级都有定义 |
| R07 | 冻结与滚动 | 顶部列头、左侧行头与角区冻结；鼠标、触控板和键盘双向移动；支持按逻辑行列或成员定位、resize 和 DPR 变化 |
| R08 | 有界虚拟化 | 绘制、表头/pane 检索和高基数取数均按窗口工作；缓存有上限；不分配行数×列数的稠密矩阵；支持浏览器原生滚动范围之外的逻辑位置 |
| R09 | 基础图形 | bar、point、line、rect、text；bar 支持分组与正负堆叠；rect 支持 band×band 热力单元；text 显示输入值；line 支持缺失值断线 |
| R10 | 轴、范围与编码 | 线性、时间与 band 位置；按字段族共享、按前缀共享、pane 独立、固定 domain；分类/连续颜色、数值格式与统一图例；滚动不改变 domain |
| R11 | 顺序和折叠 | 遵循外部给定的成员顺序；发出排序/折叠请求并接受受控更新；需要的汇总结果由外部供给；空组合保留几何，不补假零 |
| R12 | 统一交互 | tooltip、单选、修饰键多选、视口内框选、清空；跨 pane 选中精确 tuple，切换后端与滚动不丢选择；发出宿主可消费事件 |
| R13 | GW 配套接入 | 沿用 renderer 选择、字段操作、过滤结果、格式、存储、undo/redo 和公开 renderer/ref；库不直接依赖 computation/store |
| R14 | 导出与可访问性 | 当前视口 PNG/SVG；有限逻辑范围 SVG；大范围分页 SVG；键盘焦点、可访问名称、按需访问数据和折叠控件 |
| R15 | 完整性与诊断 | 区分加载中、无数据、完整、预览/截断、不可支持、资源超限；旧异步结果不得覆盖新工作表；可取消加载与导出 |
| R16 | 现有 specification 为入口 | 同一份 IChart 可选择 native renderer；兼容场景切换时只改 renderer/backend 选择，不转换文档，不丢 encodings/config/layout |
| R17 | Vega-Lite 局部兼容 | 对明确列出的 mark/encoding/scale/axis 等子集复用命名和行为；保持既有输入正规化路径；不把完整 Vega-Lite 编译器作为新路径依赖 |

R04 由现有 GW 字段类型与行列约定决定默认显示。只有确实缺少的能力才在现有结构中添加可选兼容配置，例如分面角色或前缀范围；不另建 AxisExpr DSL。未定义的组合返回诊断，不能静默截断字段。原 spec 的计算表达式由 GW 处理，native renderer 绑定对应结果列。

R09/R10/R17 的映射按 [design doc 的 spec 与兼容规则](./worksheet-renderer-design.md#3-现有-spec-映射与-vega-lite-局部兼容)实施。首版每个 pane 目标至多一个 mark 配置，可以有多个并列目标；这不等于一个 pane 内的多标记层。

R12 的框选只选当前视口内完成绘制的标记，不因框经过尚未加载区域而猜测其数据。框选时不自动滚动；按维度谓词选择整组属于显式宿主操作。首版提供联动事件，但不新增完整 dashboard 联动编辑器。

## 5. 项目范围外与后续渲染能力

### 5.1 不属于本项目

Tableau LOD 不属于研究、语法兼容、实现或验收范围，也不列为 GW 或其他模块需要新增的能力。本项目没有复刻 Tableau 计算表达式的工作项。

| 范围外事项 | 边界 |
| --- | --- |
| 计算语言、运算符、查询规划与执行器研发 | 使用现有固定运算、计算 DSL 和 SQL；不新增、迁移或重写计算体系 |
| 总计/小计/Top N 等指标的计算与分析编辑器 | 不是本期任务；已有结果可作为普通输入显示 |
| VizQL 或第二套用户 specification | 继续演进现有 GW 可视化 DSL，不建设替代语言 |
| 数据库/SQL/computation provider 研发 | 本期只做结果读取接口适配，不扩展计算后端 |
| 完整 Vega-Lite spec/runtime 兼容、Tableau 私有文件、主题或像素完全兼容 | 不作为交付承诺；局部语法兼容按清单验收 |

### 5.2 可后续考虑的渲染能力

| 能力 | 本轮处理 |
| --- | --- |
| 双轴、多标记层、共享轴多度量混绘 | 保留模型扩展位置，首版给出 unsupported 诊断 |
| 总计/小计的专门显示样式 | 只展示输入的现成结果，不计算指标 |
| 地图、极坐标、饼图、箱线图、误差带、复杂动画 | 旧路径继续承载，新路径不静默模拟 |
| 无限点数的单 pane、自动采样、WebGL/WebGPU | 不承诺；可见 mark 超预算时明确提示，不能偷偷采样 |

## 6. 关键正确性验收

| ID | 固定用例与断言 |
| --- | --- |
| A01 | 两轴同时使用 3、5、10、20 层结构；所有字段仍存在，父子关系和排序稳定；在预算内不存在按深度切换模板的分支 |
| A02 | U1 中输入 2 个 Region、每个 3 个 Category、2 个 Year、2 个数值字段分支且组合齐全，得到 24 个 pane；Subcategory 位于 pane 内；输入值保持不变 |
| A03 | 给定 Category/Product 只有 Furniture/Chair、Office/Paper：同轴嵌套保留两个实际路径；分别放入行列后保留四个交叉槽位，两处为空，不生成假记录或零值 |
| A04 | null、字符串 `"null"`、数字 `1`、字符串 `"1"`、带分隔符的成员不会错误合并；父节点不同的同名子成员有不同身份 |
| A05 | 展开/折叠后显示宿主提供的对应记录和值；没有提供折叠行的值时显示约定的空状态/加载状态，不自行生成父值；双向折叠均如此 |
| A06 | 滚动前后 shared/prefix/pane/fixed domain 不变；pane domain 覆盖该 pane 全部数据；堆叠含正负累计端点；不同单位不误共享轴 |
| A07 | 选中 `(East, Chair)` 和 `(West, Paper)` 只发出这两个目标，不扩成四种组合，也不生成查询谓词；排序、滚动、切换后端不改变身份 |
| A08 | 同一个完整 Scene 在 Canvas/SVG 中，mark 数、坐标、clip、文字内容和命中身份一致；像素抗锯齿允许差异，布局误差目标不超过 1 CSS px |
| A09 | 快速滚动、改过滤和重排后乱序返回旧响应，不能污染新快照；加载中的空槽与确实无数据的槽位显示不同 |
| A10 | 表头跨过视口边界仍显示对应祖先；四个绘制区域无覆盖泄漏；滚动到最后一个逻辑位置，首尾、焦点和返回跳转均准确 |
| A11 | line 不跨 pane 或跨 series 连线；显式 null 断线；部分可见线段不因端点在裁剪区外而消失；热力单元和文本在 cell 模式中正确定位 |
| A12 | 导出的逻辑范围包含未访问过的数据；分页不重复遗漏；视口导出忠实保留当前滚动和冻结头；取消后释放任务与内存 |
| A13 | 工作表保存/重载、undo/redo、受控 props、导入导出不丢字段实例与语义；旧 IChart、Vega-Lite、Observable Plot 和 PivotTable 回归通过 |
| A14 | 关键路径可用键盘完成；焦点与滚动一致；屏幕阅读器可读取工作表摘要、当前位置、展开状态与按需数据；DOM 数不随整表单元数增长 |
| A15 | 同一份现有 IChart 在受支持的 Vega-Lite/Observable Plot/native 路径中保留字段绑定、数值、有效域与格式；切换只改变 renderer/useSvg；深层新能力在旧后端不支持时明确诊断，不删除字段 |
| A16 | 声明兼容的局部 Vega-Lite 配置有固定输入/输出样例；不支持的 transform/params/表达式等不被静默接受；原 spec 的 aggName/filters 仍可由 GW 处理，不因切换 native 而丢失 |

A05 使用预先准备的记录验证受控更新和输入值保持不变，不要求实现或验证新的指标算法。输入相同数值时，库不因其业务名称不同而换计算逻辑；现有计算模块的测试不是本期新增交付项。

## 7. 规模和性能预算

以下是本版验收预算，实际结果见实施记录及其引用的独立报告。历史候选结果不能自动沿用到新构建；预算变更必须记录，正确性与单 Canvas 要求不变。

### 7.1 基准集

| 基准 | 数据与结构 | 用途 |
| --- | --- | --- |
| B1：显示语义集 | A01–A16 的既有 IChart 与确定性数据；深层、缺失组合、长文本、不同单位及兼容配置 | 映射、两后端、供数与事件边界的正确性基准 |
| B2：日常工作表 | 10,000 个非空 pane，6 层行列结构；视口名义容量最多 100 个完整格，连续滚动额外保留相交边缘格；最多 20,000 个可见 marks | Canvas 帧预算、命中与生命周期 |
| B3：高基数稀疏表 | 100,000 个行叶位置 × 1,000 个列叶位置，1 亿逻辑槽位；1,000,000 条已准备显示记录，6 层不均匀层级；每 pane 记录有限 | 无稠密矩阵、有界取数与缓存、随机跳转 |
| B4：超长坐标 | 使用可随机定位的程序化 RenderDataSource，逻辑总长超过浏览器实测滚动上限，包含接近末尾的跳转 | 独立验证滚动坐标映射；不冒充真实数据性能 |
| B5：SVG 工作表 | 与 B2 同样的语义，最多 5,000 个可见 marks、10,000 SVG 元素，包含相交边缘格的节点 | 可交互 SVG、节点回收与导出一致性 |

"1 亿逻辑槽位"不是 1 亿真实 pane 对象，也不是 1 亿 mark。库的基准报告记录输入记录数、两轴叶数、逻辑槽位、非空 pane、实际加载 pane、绘制 mark 和 SVG 元素。GW 端到端报告另列其原始行数与聚合行数，库不负责获知这些外部信息。

2026-11-06，S2 连续像素滚动验收修正了格子预算的定义。名义容量按视口尺寸除以固定格子尺寸向上取整计算，不随滚动偏移改变。10×10 视口偏移 1 px 会相交 11×11 个格子，因此必须容纳这些边缘格；名义容量不超过 100 时，长条形视口最多相交 202 个格子。控制器整窗数据最多 40,400 条、单 pane 最多 20,000 条，绘制仍受 20,000 个可见 marks、SVG 5,000 hits/10,000 元素及 128 MiB 约束。可选预取范围最多 100 格，不能排挤必需视口。这个修正保留原基准密度，验收增加小于一个格子的连续偏移，不能仅用整格跳转证明滚动可用。

B3 必须使用实际记录及索引化供数接口测量，不能只用空白占位通过。GW 配套集成另验真实计算结果的供数，不要求本库实现数据库 provider。外部准备时间与库内显示索引准备时间分开披露；库内索引和首帧准备不得漏出计时。

### 7.2 验收预算

| 项目 | 预算与计时边界 |
| --- | --- |
| 冷首帧 | 数据快照、首屏所需元数据和 marks 已就绪，到首帧绘制完成，p95 ≤ 500 ms；另报用户操作到首帧的端到端时间 |
| Canvas 连续滚动 | B2/B3 热缓存下 JS 检索、布局、绘制提交总耗时 p95 ≤ 16 ms；浏览器呈现帧间隔 p95 ≤ 33 ms，两项分开统计 |
| SVG 连续滚动 | B5 热缓存下更新提交 p95 ≤ 32 ms；不得用取消冻结头、减少字段或错算 domain 达标 |
| 交互反馈 | hover/选择从输入到视觉反馈 p95 ≤ 50 ms；不含宿主联动网络请求 |
| 折叠/顺序更新 | 宿主提交新数据/成员顺序到稳定画面 p95 ≤ 150 ms；等待宿主响应时 100 ms 内进入明确加载状态 |
| Canvas 位图 | `ceil(viewportWidth × DPR) × ceil(viewportHeight × DPR)`，不随逻辑槽位数增长；允许显式限制有效 DPR |
| 运行时驻留内存 | B3 中数据窗口、层级窗口、布局、Scene、命中和缓存合计目标 ≤ 128 MiB；位图另计，完整输入与供数索引内存单独披露，不将总内存误报成运行时内存 |
| 窗口读取 | 默认总并发 ≤ 4；合并相邻窗口、去重同版本同范围请求；热缓存纯滚动不发重复请求；不逐 pane 发请求 |
| 生命周期 | 1,000 次窗口移动及 50 次挂载/销毁，资源数回到基线；强制 GC 后同一基线场景存活堆增量 ≤ 10%，不持续线性增长 |

统一使用 1440×900 CSS px、DPR 2、60 Hz 桌面测试环境，固定字体和数据种子；报告 CPU、内存、操作系统、浏览器版本、构建版本。冷首帧至少 30 次独立样本，滚动每轮至少 300 帧、5 轮；报告每轮与合并 p50/p95、最大值、long task 和掉帧。正式浏览器矩阵为桌面 Chromium、Firefox、Safari 的发布时固定版本；性能门槛先在记录的参考机器上验收，其余完成兼容与严重退化检查。

单 pane 超过 mark 预算、SVG 元素超限、外部供数缺少完整域时，允许明确拒绝或由用户选择缩小范围。不得截断后仍显示为完整工作表。具体超限默认值和错误提示在 S0 固定。

B3 的一次性索引和首屏预算在 2026-11-06 的 S2 实测后补齐，以下与预建供数源的 500 ms 冷帧指标分别验收。参考机器、浏览器及构建必须随报告固定，至少 30 次独立重建样本，不以单次最快值替代。基准生成输入属于测试准备，生产环境外部查询等待不属于本库性能责任。

| B3 完整准备项目 | 冻结目标 |
| --- | --- |
| 库内显示索引准备 | p95 ≤ 3,500 ms |
| 完整 prepared records 已有，到 adapter、索引和首屏呈现完成 | p95 ≤ 4,000 ms |
| 固定百万记录基准的生成输入到首屏呈现 | p95 ≤ 5,000 ms，单独报告 input generation；不宣称生产 SQL 端到端保证 |
| 独立 Node 基准进程峰值 | RSS high-water ≤ 2 GiB，包括完整输入、供数索引和运行时，报告启动基线 |
| 完整输入与索引保留时的 GC 后驻留 | heapUsed + arrayBuffers ≤ 1.25 GiB，同时报告 RSS、external 和基线差；arrayBuffers 属于 external，不重复相加 |

首次优化后的 30 次浏览器候选测量中，索引 p95 2,799 ms，剔除输入生成后的首屏 p95 2,853 ms，全程 p95 3,524.9 ms。目标留出重复运行余量，原 500 ms 预建源冷帧、滚动、交互和 128 MiB 运行时预算不变。旧基线与新结果均保留，最终冻结构建必须重新测量。报告分列外部准备、adapter、索引、读取等待、布局、Scene、绘制提交和呈现，不能把库内准备移出计时。

## 8. 首版发布条件

R01–R17 完成；A01–A16 通过；B1–B5 有可重复执行的记录；现有 spec 的保存、输入正规化、renderer 切换回归通过；已准备数据的完整/按需两种入口均可用。源码导入测试通过但缺少正式构建产物、只有 SVG 导出、或者只有空占位滚动流畅，都不能单独算首版完成。新顶层 spec、数据库查询计划与表计算实现不属于交付内容。

发布物包含子包、现有 spec 的映射/兼容清单、必要的原 schema 兼容更新、接入说明、能力矩阵及基准记录。日期与工期在技术验证后确定，不能用历史实验的测试记录替代本版验收。
