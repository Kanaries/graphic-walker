1. 初审独立阅读 alignment、requirements、design，并核对当前源码。主 agent 的并行代码笔记没有作为初审提示提供。初审提出 10 项具体意见，认为方向成立，可做 S0，但实施前仍需补齐若干契约。

3. 复审修订后的技术设计与 alignment D9，确认 P1–P10 均有足够处理，补充时间柱图、非位置通道图例和少量版本/状态文字。

## 讨论后确定的处理

- 首版的分组柱、前缀共享域继续保留，不因当前 schema 缺字段而移出需求。通过既有 IChart.layout 的小范围可选字段表达，保持原 schema 地址。
- 成员顺序与记录身份由 adapter/source 准备。库不根据业务粒度生成键，也不新增按指标排序的计算逻辑。GW 适配可读取现有 workflow 已声明的分组列来标识结果，不执行新的分组计算。
- snapshotId 标识数据内容，presentationId 标识排序、展开和显示计划。旧 rank 不能用于新布局；已证明内容不变的 pane 记录才可按稳定路径复用。
- 旧后端收到无法表达的新显示含义时保留 spec 并显示能力空态。切换入口由用户触发，不自动降级为另一张部分图表。该行为通过 alignment D9 单列记录。
- 连续位置柱保留原 time/linear 刻度，使用给定区间或静态像素宽度，不做分桶；两端裁剪/padding 进入 S0 fixture。非位置通道 independent 不支持时给能力诊断，不把请求强改为 shared 后出图。
- 主 agent 补充核对了现有 e.item.mark 事件依赖、函数式 scales 和四个导出 ref。新 adapter 使用结构化 target/raw，窗口数据不冒充完整 values，旧导出方法明确为当前完整视口。

## 验证边界

本轮完成文档与源码对照、独立审核和文档一致性检查。没有实施 renderer，没有运行产品测试或性能基准。性能数值仍为目标，不能引用本次审核作为已达到性能的证据。

S0 必须验证三种浏览器的滚动输入与超长坐标、完整/窗口供数和堆叠域一致性、真实记录索引的时间与内存、Canvas/SVG 几何和事件一致性、GW 稳定身份与旧接口适配。通过测量后固定预算；本次确定的职责边界和协议含义保持一致。
